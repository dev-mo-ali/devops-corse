Docker Hands-on Training — Step by Step

Ubuntu + Docker Engine22 steps100-mark assignment

As a Docker trainer, I recommend learning Docker commands in the order of the container lifecycle, rather than memorizing individual commands.

We will use Ubuntu with Docker Engine installed and Nginx as our first application. You can execute each command on your Ubuntu server and observe the results. The outputs below are illustrative, not executed on your server.

1. Understand the Docker workflow

The CLI sends your command to the daemon. The daemon pulls a missing image from the registry, creates a container, and starts its main process.

2. Verify Docker installation

Lab example
docker --version

Display the installed Docker version.

Lab example
docker version

Display detailed information about the Docker Client and Docker Server.

Lab example
docker info

Display information about the Docker environment, including containers, images, storage driver and available resources.

Lab example
sudo systemctl status docker

Check whether the Docker service is running.

If you receive a permission-denied error when executing Docker commands, use sudo docker instead of docker.

3. Run your first container

Lab example
docker run hello-world

Behind the scenes, Docker performs the following operations:

  1. Docker CLI sends a request to the Docker daemon.
  2. Docker checks whether the image exists locally.
  3. Docker downloads the image from Docker Hub if necessary.
  4. Docker creates a new container.
  5. Docker starts the container.
  6. The application prints its message and exits.

Expected output:

Lab example
Hello from Docker!
This message shows that your installation appears
to be working correctly.

4. Working with Docker images

An image is a read-only template containing an application, its dependencies and configuration.

4.1 Search for an image

Lab example
docker search nginx

Search Docker Hub for Nginx images.

4.2 Download an image

Lab example
docker pull nginx

Download a specific image tag:

Lab example
docker pull nginx:alpine

The Alpine variant is based on a lightweight Linux distribution.

4.3 List downloaded images

Lab example
docker images

Example output:

Lab example
REPOSITORY    TAG       IMAGE ID       SIZE
nginx         latest    a72860cb95fd   192MB
nginx         alpine    c7b4f26a1e23   48MB
hello-world   latest    74cc54e27dc4   10kB

Alternative syntax:

Lab example
docker image ls

4.4 Inspect an image

Lab example
docker image inspect nginx

View image metadata, environment variables, architecture, layers and default configuration.

4.5 View image layers

Lab example
docker history nginx

Understand how the image was built.

5. Creating and running containers

5.1 Create a container without starting it

Lab example
docker create --name my-nginx nginx

Check the container:

Lab example
docker ps -a

The status will be Created.

5.2 Start the container

Lab example
docker start my-nginx

5.3 Create and start in one command

Lab example
docker run --name web-server -d nginx

docker run combines container creation and startup.

7. Port mapping

The Nginx containers we created are running, but we have not published their ports to the host.

Execute:

Lab example
docker run -d \
  --name nginx-web \
  -p 8080:80 \
  nginx

Test the application:

Lab example
curl http://localhost:8080

Or visit from your browser:

Lab example
http://YOUR_EC2_PUBLIC_IP:8080

If using EC2, allow TCP port 8080 from your IP address in the security group.

Experiment with multiple containers

Lab example
docker run -d --name web2 -p 8081:80 nginx
docker run -d --name web3 -p 8082:80 nginx

You now have three independent Nginx containers.

Containers can use identical internal ports because they have isolated network environments. However, they cannot bind the same host IP, port and protocol simultaneously.

9. Execute commands inside a container

Lab example
docker exec -it nginx-web bash

You are now inside the running container.

Execute these Linux commands:

Lab example
hostname

ls
cat /etc/os-release
ls /usr/share/nginx/html

Modify the default Nginx page:

Lab example
echo "Welcome to Docker Training" > /usr/share/nginx/html/index.html

Exit the container:

Lab example
exit

Test again from your host:

Lab example
curl http://localhost:8080

Expected output:

Lab example
Welcome to Docker Training

docker run vs docker exec

docker rundocker exec
Creates a new containerUses an existing container
Starts a containerStarts an additional process
Requires an imageRequires a running container

You can also execute a command without opening a shell:

Lab example
docker exec nginx-web nginx -t

11. Copying files

From host to container

Create a file on your Ubuntu host:

Lab example
echo "My Docker Website" > index.html

Copy it:

Lab example
docker cp index.html nginx-web:/usr/share/nginx/html/index.html

From container to host

Lab example
docker cp nginx-web:/etc/nginx/nginx.conf ./nginx.conf

Think of docker cp as copying files between two separate filesystems.

12. Docker volumes

Container data stored in its writable layer is lost when the container is removed.

Volumes allow data to exist independently of the container.

Create a volume

Lab example
docker volume create web-data

List volumes

Lab example
docker volume ls

Inspect the volume

Lab example
docker volume inspect web-data

Mount the volume

Lab example
docker run -d \
  --name persistent-web \
  -p 8083:80 \
  -v web-data:/usr/share/nginx/html \
  nginx

Write some data:

Lab example
docker exec persistent-web sh -c \
  'echo "Persistent data" > /usr/share/nginx/html/index.html'

Delete the container:

Lab example
docker rm -f persistent-web

Create a new container using the same volume:

Lab example
docker run -d \
  --name persistent-web-new \
  -p 8083:80 \
  -v web-data:/usr/share/nginx/html \
  nginx

Test:

Lab example
curl http://localhost:8083

Expected output:

Lab example
Persistent data

Lesson: The container was deleted, but the volume and data survived.

13. Bind mounts

A bind mount connects a specific host file or directory to a container.

Lab example
mkdir -p ~/docker-lab/website
cd ~/docker-lab/website

echo "My Docker Website" > index.html

Run a container:

Lab example
docker run -d \
  --name bind-web \
  -p 8084:80 \
  -v "$(pwd):/usr/share/nginx/html:ro" \
  nginx

Modify the file on the host:

Lab example
echo "Updated website" > index.html

Test:

Lab example
curl http://localhost:8084

The change is immediately available without rebuilding or restarting the container.

Docker volumeBind mount
Managed by DockerManaged by the host user
Identified by a volume nameIdentified by a filesystem path
Suitable for database persistenceSuitable for source code and configuration
More independent of host directory layoutDependent on host directory layout

14. Docker networking

List networks

Lab example
docker network ls

Create a custom network

Lab example
docker network create app-network

Inspect the network

Lab example
docker network inspect app-network

Run two containers on the same network

Lab example
docker run -d \
  --name backend \
  --network app-network \
  nginx
Lab example
docker run -d \
  --name client \
  --network app-network \
  alpine sleep infinity

Test communication between containers:

Lab example
docker exec client ping -c 3 backend

Test HTTP communication:

Lab example
docker exec client wget -qO- http://backend

Notice that we use the container name backend instead of its IP address.

Docker provides automatic DNS resolution for containers on user-defined bridge networks.

This concept is important when connecting Laravel, MySQL, Redis and other services.

15. Environment variables

Environment variables allow you to configure applications when starting containers.

Lab example
docker run --rm \
  -e APP_ENV=production \
  -e APP_NAME=MyApp \
  alpine env

For a practical database example:

Lab example
docker run -d \
  --name mysql-db \
  --network app-network \
  -e MYSQL_ROOT_PASSWORD=LabPassword123 \
  -e MYSQL_DATABASE=training \
  mysql:8.4

Check startup progress:

Lab example
docker logs -f mysql-db

After MySQL finishes initializing, connect to it:

Lab example
docker exec -it mysql-db mysql -u root -p

The password above is only for a disposable training environment. Do not use it in production.

16. Building your own Docker image

So far, we have used existing images. Now we will create our own.

Create a project

Lab example
mkdir -p ~/docker-lab/my-app
cd ~/docker-lab/my-app

Create an HTML file

Lab example
echo "<h1>My Custom Docker Application</h1>" > index.html

Create a Dockerfile

Lab example
nano Dockerfile
Lab example
FROM nginx:alpine

COPY index.html /usr/share/nginx/html/index.html

EXPOSE 80
InstructionPurpose
FROMDefine the base image
COPYCopy files into the image
EXPOSEDocument the intended application port

Build the image

Lab example
docker build -t my-website:v1 .

Run your custom image

Lab example
docker run -d \
  --name my-application \
  -p 8085:80 \
  my-website:v1

Test:

Lab example
curl http://localhost:8085

Create a new version

Lab example
echo "<h1>Application Version 2</h1>" > index.html

docker build -t my-website:v2 .
Lab example
docker images

You now have two versions of your application image.

17. Docker Registry

Push your custom image to Docker Hub.

Lab example
docker login

Tag your image:

Lab example
docker tag my-website:v1 YOUR_USERNAME/my-website:v1

Push the image:

Lab example
docker push YOUR_USERNAME/my-website:v1

Download it on another server:

Lab example
docker pull YOUR_USERNAME/my-website:v1

This is the foundation of container-based CI/CD.

For AWS environments, Amazon ECR can serve as your private container registry.

18. Resource limits and restart policies

Run a container with restricted CPU and memory:

Lab example
docker run -d \
  --name limited-nginx \
  --memory=128m \
  --cpus=0.5 \
  --restart=unless-stopped \
  nginx
OptionMeaning
--memory=128mMaximum memory of 128 MiB
--cpus=0.5CPU usage equivalent to half a CPU
--restart=unless-stoppedRestart automatically unless explicitly stopped

Update an existing container:

Lab example
docker update --memory=256m --memory-swap=512m --cpus=1 limited-nginx

These resource restrictions are implemented using Linux Control Groups (cgroups).

19. Docker Compose

Instead of manually executing multiple docker run commands, define your services in a YAML file.

Lab example
mkdir -p ~/docker-lab/compose-app
cd ~/docker-lab/compose-app
nano compose.yaml
Lab example
services:
  web:
    image: nginx:alpine
    ports:
      - "8090:80"
    restart: unless-stopped

  database:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: LabPassword123
      MYSQL_DATABASE: training
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:

Docker Compose commands

CommandPurpose

docker compose pullDownload images

docker compose psList services

Be careful with down -v, especially when running databases.

20. Removing resources and cleaning up

Remove a stopped container

Lab example
docker stop nginx-web
docker rm nginx-web

Force remove a running container

Lab example
docker rm -f web2

Remove an image

Lab example
docker rmi my-website:v2

Remove unused resources

CommandWhat it removes
docker container pruneAll stopped containers
docker image pruneDangling images
docker image prune -aUnused images
docker network pruneUnused networks
docker volume pruneUnused anonymous volumes by default
docker builder pruneUnused build cache
docker system pruneMultiple categories of unused resources

Warning: Prune commands operate across the Docker host, not just your current project. Avoid running them blindly on production servers.
