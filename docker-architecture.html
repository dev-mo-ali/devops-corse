Section 1

What is Docker

Docker provides tools to package applications and run them in containers. Packaging the application with its dependencies reduces differences between development, testing, and production. Linux containers share the Docker host’s kernel, which helps keep their resource overhead low.

Docker is one of several container tools. Explore the wider ecosystem, then distinguish Docker, docker, and dockerd and see where containerd fits.

Dockerfile

A text file containing build instructions, such as selecting a base image and copying application files.

Image

A reusable, read-only template containing filesystem layers and configuration used to create containers.

Container

An instance created from an image, with its own writable layer and process environment. It can be running or stopped.

Follow the lifecycle. Build an image from a Dockerfile, push it to a registry, pull it onto another compatible host, and create a container from it. Docker Hub is a hosted registry for finding and sharing images.

Introduction adapted from What is Docker? — GeeksforGeeks.

Topic 06 · Section 1.1

Docker is one way to run containers

Containers are a way to package and isolate workloads. Docker is one platform for building, running, and managing them. Other tools can use the same underlying Linux features and compatible container images.

Docker Engine is optional for Kubernetes. A cluster can use containerd directly. Docker Engine integration uses an adapter such as cri-dockerd.

OCI standards help tools exchange images and run containers. Compatibility still depends on the image’s operating system, CPU architecture, and required runtime features.

See containerd, Podman, and Kubernetes container runtimes.

Topic 06 · Section 1.2

Tools for virtual machines

A hypervisor supplies virtual hardware. A management platform adds controls for creating, operating, and organizing VMs. Some platforms also manage Linux containers.

ToolRoleExample use
VMware vSphereEnterprise virtualization platform, with ESX/ESXi hosts and vCenter management.Manage VMs across a data center.
Proxmox VEOpen-source platform combining KVM-based VMs and LXC containers.Manage both workload types through one web interface.
Microsoft Hyper-VHypervisor technology in supported Windows and Windows Server editions.Run guest operating systems on a Windows host.
KVMVirtualization support in the Linux kernel, commonly paired with QEMU and management tools.Provide the virtualization foundation beneath a Linux VM platform.

VMs and containers can work together. A VM created by one of these platforms can itself be a Docker host or a Kubernetes node.

Hyper-V also supports Hyper-V isolation for Windows containers, where a container runs inside an optimized VM with its own kernel.

Topic 06 · Section 1.5

Docker, docker, and dockerd

Docker names the broader container platform. In a terminal, docker names its command-line client. dockerd is the Docker daemon: a service that keeps running in the background.

NameWhat it isWhat you do with it
DockerThe platform and tool ecosystem.Build, share, and run containerized applications.
dockerThe CLI client you invoke.Send requests such as docker ps or docker run.
dockerdThe server process serving the Engine API.Manages Docker images, containers, networks, and volumes; delegates runtime work to containerd.
Docker EngineThe client/server technology: daemon, API, and CLI.Provides the core container engine.
Docker DesktopA desktop application bundling Engine and developer tools.Manages the local backend and provides a graphical interface.

Remember the “d”: dockerd means Docker daemon. The client sends a request; the daemon handles it. They can run on different machines.

References: Docker Engine, docker CLI, dockerd reference, and Docker Desktop.

Topic 06 · Section 1.6

Where does containerd fit?

dockerd and containerd are different components that work together. Docker adds the user-facing tools and Engine API; containerd is a separate runtime project that can also serve other platforms.

dockerd: Docker management

Handles Docker API requests and coordinates images, network configuration, mounts, and container creation.

containerd: runtime management

Provides image and container lifecycle services. In the usual Linux stack, it works through a shim and an OCI runtime such as runc.

They are layers, not interchangeable commands. The Docker CLI expects the Docker Engine API. A standalone containerd service does not provide that API; tools such as nerdctl can talk to containerd.

Kubernetes can use containerd through CRI without dockerd. Docker-compatible images do not require Docker Engine on every machine that runs them.

Based on Docker: containerd vs. Docker, the containerd project, nerdctl, and Kubernetes runtimes.

Topic 06 · Section 1.7

See the client and server separately

On your Windows 11 laptop, start Docker Desktop and wait for its engine to be ready. Open PowerShell and inspect the installation:

PowerShell · client only
docker --version

This prints the installed CLI version. It can succeed even when the daemon is unavailable.

PowerShell · client and server
docker version

Look for Client (the CLI) and Server (the selected Engine). The server section can also list containerd and runc. Versions and fields depend on your installation.

PowerShell · connection and running containers
docker context show
docker ps

The context identifies the selected connection; docker ps queries its daemon. An empty list can simply mean no containers are running.

If the client works but the server cannot be reached: check Docker Desktop's engine status and the selected connection. A working CLI alone does not prove the engine is ready.

With Docker Desktop's Linux container backend, PowerShell runs the Windows client while the daemon and containers run in a Linux environment, commonly provided by WSL 2. Docker Desktop manages that backend; this demo does not require starting dockerd manually in PowerShell.

References: docker version, CLI options, Docker contexts, and Docker Desktop with WSL 2.

Section 2

Docker Architecture

Explore the components, then follow how Docker builds, shares, and runs containers.

Components

Who handles a Docker command?

Client

The docker CLI in PowerShell sends requests through the Engine API. The active Docker context selects the endpoint. docker context ls shows which one is selected.

Docker host

The host runs dockerd, the daemon that manages containers, images, networks, and volumes. In Docker Desktop’s Linux container mode, the daemon runs in a Linux environment on your laptop.

Registry

Docker Hub and private registries distribute images. In nginx:alpine, nginx names the repository and alpine selects a tag. The short name resolves to Docker Hub’s official Nginx repository.

Compare two commands. docker --version prints the client version locally. docker ps asks the selected daemon which containers are running on its host.

Build and delivery

How does a team ship its own image?

Suppose your team adds an index.html to the class web demo. Save these two lines as Dockerfile next to that page, and build from that directory.

Dockerfile
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
  1. Build. docker build -t class-site:1 . gives the builder access to the current directory. Buildx submits the build to BuildKit, which reads the Dockerfile, reuses available layers, and produces the image.
  2. Tag and push. To share it, tag class-site:1 with a repository you can publish to. For a Docker Hub account named exampleteam, the reference could be exampleteam/class-site:1. After authenticating, the team pushes that reference to its registry.
  3. Pull and run. A second Docker host pulls the published image. Each container created from that image starts with the same page. A new page release requires a new build and a replacement container.

With a backend and database, Compose can describe the services, their shared network, and a database volume in one file. The Engine manages the resulting containers on the selected host.
