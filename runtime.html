01 / The big idea

One word. Two related meanings.

A runtime can mean the period when software is executing, or the software environment that makes execution possible.

SOURCE CODE

The instructions

The application you write: PHP, JavaScript, Python, Java, or another language.

RUNTIME ENVIRONMENT

The machinery

The interpreter, engine, libraries and system capabilities needed to execute it.

RUNTIME

The execution

When a program is actively running, using memory, CPU, files and network resources.

Simple analogy: Your source code is a recipe. The runtime environment is the equipped kitchen. Runtime is the cooking itself.
02 / Language runtimes

Node.js is not a programming language.

JavaScript is the language. Node.js is a runtime environment that executes JavaScript outside the browser, including on Linux servers.

JAVASCRIPT ON A SERVER
// app.js
console.log('Hello Moh!');

// Run from your terminal:
$ node app.js
Hello Moh!

Node.js uses the V8 JavaScript engine and provides APIs for files, networking, processes and other server-side capabilities.

03 / Container runtimes

Who actually starts a container?

A container image is a packaged filesystem and configuration. It is not a running container. Software such as Docker Engine, containerd and runc cooperates to start the processes.

04 / Kubernetes context

Where does Kubernetes fit?

Kubernetes uses the Container Runtime Interface (CRI) to request container operations from a compatible runtime implementation.

  • kubelet manages Pod execution on a node.
  • containerd or CRI-O can provide the CRI runtime service.
  • runc is a common low-level OCI runtime beneath them.
Remember: Kubernetes is an orchestrator, not a JavaScript runtime, and not itself the low-level container creator.

05 / Put it all together

Two runtimes. Different jobs.

Imagine a Docker container running a Laravel application. Both terms are valid, but they refer to separate responsibilities.

Laravel PHP code handles HTTP requests and business logic.
PHP executes Laravel code inside the container.
containerd / runc enable and manage the containerized process lifecycle.
The Linux kernel runs processes and provides isolation and resource controls.
The PHP runtime does not replace the container runtime. One executes application code; the other is part of the machinery for running containerized processes.
