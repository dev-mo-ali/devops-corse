01 / WHAT IS A SUBMODULE?

A repository inside another repository

A submodule lets the parent project use the contents of an independently versioned Git repository in one of its directories, while tracking exactly which commit should be checked out.

INDEPENDENT HISTORY

Two repositories

The parent and child have separate branches, commits, remotes, and object databases. Committing in one does not automatically commit in the other.

REPRODUCIBLE STATE

Pinned commit

The parent stores a gitlink referring to a submodule commit SHA. Teammates can check out the exact same child version.

SHARED CODE

Reusable components

Useful for code shared across services, infrastructure modules, firmware components, or separately maintained libraries.

Mental model: Your parent repository stores a reference saying “for directory packages/shared-auth, use commit 7a91c2f from the child repository.” It does not turn the child's files into ordinary tracked parent files.

03 / STARTING WITH SUBMODULES

Add your first submodule

Example: your Laravel platform consumes an independently maintained authentication library. Replace the example URL with an accessible repository you control.

Step 1 — Add the child repository

git submodule add https://github.com/ORG/shared-auth.git packages/shared-auth git status

Git creates the child working directory, a .gitmodules entry, and a staged gitlink entry for the submodule path.

FILE A · .gitmodules

Tracked configuration

[submodule "packages/shared-auth"] path = packages/shared-auth url = https://github.com/ORG/shared-auth.git

Other developers use this path-to-URL mapping to fetch the child. Choose a URL they can access.

ENTRY B · GITLINK

Mode 160000

git ls-files --stage packages/shared-auth # 160000 7a91c2f... 0 packages/shared-auth

The parent tracks a commit ID for the child path, not the complete file contents in that directory.

Step 2 — Record and publish the parent change

git add .gitmodules packages/shared-auth git commit -m "Add shared-auth submodule" git push origin main

The child commit must also be available in its remote repository before others can check it out.

04 / DAY-TO-DAY WORKFLOW

Clone, initialize, update

RECOMMENDED CLONE

Clone everything in one command

git clone --recurse-submodules https://github.com/ORG/laravel-platform.git

Clones the parent, initializes submodules, and checks out pinned child commits (including nested submodules).

ALREADY CLONED?

Initialize after cloning

git submodule update --init --recursive

Use when submodule folders are empty or a new submodule was added to the parent.

MATCH PARENT SHA

Restore the pinned version

git submodule update --init --recursive

By default, updates checkout the recorded gitlink commit. It is not the same as “get latest from remote.”

INTENTIONAL UPGRADE

Fetch newer child version

git submodule update --remote packages/shared-auth git diff --submodule git add packages/shared-auth git commit -m "Bump shared-auth revision"

--remote uses the configured remote-tracking branch; review changes and record the new pointer in the parent.

Two easily confused commands: git submodule update checks out the commit the parent already records; git submodule update --remote fetches and updates the child toward a configured remote branch, making the parent gitlink potentially dirty until committed.
05 / COLLABORATING ON SUBMODULE CODE

Working inside the child repository

If you change code inside a submodule, the child needs its own commit and push. The parent then commits the updated gitlink.

1. Enter child and work on a branch
cd packages/shared-auth git switch -c fix/login-validation # edit and test child files
2. Commit and push the child first
git add . git commit -m "Fix login validation" git push -u origin fix/login-validation

Merge the child changes into a shared branch as your team requires. Ensure the target commit is reachable by teammates.

3. Update the parent pointer
cd ../.. git status git add packages/shared-auth git commit -m "Update shared-auth submodule" git push origin main
Why push the child first? If the parent points to a child SHA that exists only on your laptop, colleagues and CI/CD cannot fetch it. A parent commit does not upload the child commit objects.
06 / GIT INTERNALS

Where are the Git objects?

PARENT REPOSITORY

.gitmodules and gitlink

.gitmodules is a tracked text file for URL and path metadata. A tree entry with mode 160000 records the selected child commit SHA. The parent repository does not include the child’s full history.

git ls-tree HEAD packages/shared-auth git show --submodule=log --stat HEAD
CHILD STORAGE

.git/modules directory

In a typical modern checkout, the submodule directory contains a .git file pointing to metadata stored under the parent’s .git/modules/.... The child still has its own object database and HEAD.

cat packages/shared-auth/.git git -C packages/shared-auth rev-parse HEAD git submodule status
Detached HEAD is expected: git submodule update usually checks out the exact child commit directly, rather than a local branch. Create or switch to a child branch before making commits you intend to maintain.
07 / TROUBLESHOOTING

Common problems and fixes

Submodule directory looks empty

You cloned the parent without recursively initializing submodules.

git submodule update --init --recursive

Submodule appears modified (new commits)

Your child checkout points to a different commit than the parent's recorded gitlink. Decide whether to commit the new pointer or restore the pinned one.

git diff --submodule git submodule status # After safeguarding child work: git submodule update --init packages/shared-auth

Reference is not a tree / missing commit

The parent points to a child commit that cannot be fetched. Confirm child remote permissions and ensure that commit was pushed.

git -C packages/shared-auth remote -v git -C packages/shared-auth fetch --all git submodule status

Submodule URL changed

After updating .gitmodules, synchronize local submodule URL configuration.

git submodule sync --recursive git submodule update --init --recursive

Pull changed the parent's gitlink

Update checked-out child commits after pulling parent changes. Save local child work before checkout operations.

git pull git submodule update --init --recursive

Safely remove a submodule

Review the exact path and ensure any child work is pushed or backed up. Modern Git removes the tracked submodule with:

git rm packages/shared-auth git commit -m "Remove shared-auth submodule"

Residual metadata under .git/modules/ may remain. Avoid manually deleting it unless you have verified it is no longer needed.

08 / HANDS-ON PRACTICE

A local two-repository lab

This lab uses a local source repository and a parent repository. It avoids external dependencies. Depending on your Git security settings, local file transport for submodule cloning may require explicitly allowing the file protocol for that one command.

1. Create the child and parent repositories

mkdir git-submodule-lab && cd git-submodule-lab mkdir child && cd child git init echo "v1" > library.txt git add . && git commit -m "Library v1" cd .. mkdir parent && cd parent git init echo "Parent app" > README.md git add . && git commit -m "Initial parent"

2. Add the local child as a submodule

git -c protocol.file.allow=always submodule add ../child vendor/child git status git ls-files --stage vendor/child git add .gitmodules vendor/child git commit -m "Add child submodule"

Relative URLs resolve against the parent repository's default remote when available; in this local lab, with no default remote configured, Git resolves against the parent repository location.

3. Create a new child commit, then update the parent pointer

cd ../child echo "v2" > library.txt git add . && git commit -m "Library v2" cd ../parent git -c protocol.file.allow=always submodule update --remote vendor/child git diff --submodule git add vendor/child git commit -m "Update child to v2"

This demonstrates two independent histories: child has a v2 commit; parent has a separate commit referencing it.
