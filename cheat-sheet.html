Getting started

Create a repository or copy one that already exists.

  • Start a new repositorygit init
  • Clone an existing repositorygit clone <url>

Prepare to commit

Choose the changes that belong in the next snapshot.

  • Stage one filegit add <file>
  • Stage changes in the current directorygit add .
  • Stage selected parts of a filegit add -p
  • Move or rename a filegit mv <old> <new>
  • Remove a tracked filegit rm <file>
  • Stop tracking a file but keep it locallygit rm --cached <file>
  • Unstage one filegit restore --staged <file>orgit reset <file>
  • Unstage everythinggit restore --staged .orgit reset
  • Check the working tree and stagegit status

Make commits

Record the staged snapshot with a useful message.

  • Open an editor for the messagegit commit
  • Write the message in the commandgit commit -m 'message'
  • Stage modified tracked files and commitgit commit -am 'message'New, untracked files are not included.

Move between branches

Keep separate lines of work on named branches.

  • Switch to an existing branchgit switch <name>orgit checkout <name>
  • Create and switch to a branchgit switch -c <name>orgit checkout -b <name>
  • List local branchesgit branch
  • Sort branches by most recent commitgit branch --sort=-committerdate
  • Delete a merged branchgit branch -d <name>
  • Force-delete a branchgit branch -D <name>Check that you no longer need its unique commits.

Diff staged and unstaged changes

Compare the current files and stage with HEAD.

  • All tracked changes since HEADgit diff HEAD
  • Staged changes onlygit diff --staged
  • Unstaged changes onlygit diff

Diff commits

Compare saved snapshots and inspect a commit.

  • Show a commit and its changesgit show <commit>
  • Compare two commitsgit diff <commit1> <commit2>
  • Compare one file with a commitgit diff <commit> -- <file>
  • Summarize changed filesgit diff <commit> --statorgit show <commit> --stat

Ways to refer to a commit

Replace <commit> in an example with a branch, tag, ID, or relative reference.

  • Local branchmain
  • Tagv0.1
  • Abbreviated commit ID3e887ab
  • Remote-tracking branchorigin/main
  • Current commitHEAD
  • Three first-parent steps backHEAD^^^orHEAD~3

Discard changes

Inspect status and a diff before removing local work.

  • Discard unstaged changes in one tracked filegit restore <file>
  • Discard staged and unstaged changes in one tracked filegit restore --staged --worktree <file>orgit checkout HEAD -- <file>
  • Discard staged and unstaged changes in tracked filesgit reset --hardorgit restore --staged --worktree .
  • Preview untracked file cleanupgit clean -nd
  • Delete untracked files and directoriesgit clean -fdThe PDF abbreviates this as git clean; Git normally needs -f to delete.
  • Stash tracked changes for latergit stashUse git stash -u if you also need to include untracked files.

Careful: Restore, reset --hard, and clean -fd can permanently remove local work.

Edit history

These commands can replace commit IDs. Coordinate before rewriting shared branches.

  • Undo the last commit but keep its changesgit reset HEAD^Changes remain in the working tree and are unstaged.
  • Combine or edit the last five commitsgit rebase -i HEAD~5In the editor, change selected pick lines to fixup or squash.
  • Find a commit before a failed rewritegit reflog <branch>Inspect the reflog and confirm the target before a reset.
  • Amend the most recent commitgit commit --amend

Careful: The PDF suggests reset --hard after a failed rebase. Verify the recovery commit and save local work first.

Code archaeology

Follow history to understand when and why code changed.

  • View a branch's historygit log mainorgit log --graph mainorgit log --oneline
  • Find commits that changed a filegit log -- <file>
  • Follow a file across renamesgit log --follow -- <file>
  • Find commits that added or removed matching textgit log -G banana
  • See the last change to each linegit blame <file>

Combine diverged branches

Compare ways to bring a feature branch named banana into main.

Rebase

Replay D and E after C as new commits.

Before  main     A--B--C
        banana       \\--D--E
After   main     A--B--C
        banana         \\--D'--E'

Merge commit

Keep both histories and add a merge point M.

Before  main     A--B--C
        banana       \\--D--E
After   main     A--B--C-----M
                     \\--D--E--/

Squash merge

Record the combined feature changes as S.

Before  main     A--B--C
        banana       \\--D--E
After   main     A--B--C--S
        banana       \\--D--E

Fast-forward

When main is an ancestor of banana, move main to E.

Before  main     A--B--C
        banana         \\--D--E
After   main     A--B--C--D--E
        banana                ^

Cherry-pick

Copy one selected commit, such as E, onto main.

Before  main     A--B--C
        banana       \\--D--E
After   main     A--B--C--E'
        banana       \\--D--E
  • Rebase the feature on maingit switch bananathengit rebase mainReplays feature commits, creating new IDs.
  • Create a merge commitgit switch mainthengit merge bananaJoins both histories.
  • Squash the feature into one commitgit switch mainthengit merge --squash bananathengit commitThe feature branch remains unchanged.
  • Fast-forward main when possiblegit switch mainthengit merge bananaMoves the main pointer when it is an ancestor of banana.
  • Copy one commit onto the current branchgit cherry-pick <commit>The copied commit receives a new ID.

Restore an old file

Bring one file's content from another commit into the working tree.

  • Restore from a chosen commitgit restore --source=<commit> -- <file>orgit checkout <commit> -- <file>

Add a remote

Give another repository a short name.

  • Save a remote URLgit remote add <name> <url>

Push your changes

Send commits or tags to a remote repository.

  • Push main to origingit push origin main
  • Push the current branch to its configured upstreamgit push
  • Push a new branch and set its upstreamgit push -u origin <name>
  • Replace remote history if the workflow requires itgit push --force-with-leaseVerify the destination and coordinate with collaborators first.
  • Push tagsgit push --tags

Pull changes

Fetch, then choose how to integrate the result.

  • Fetch without integrating into your local branchgit fetch origin main
  • Fetch and rebase the current branchgit pull --rebase
  • Fetch and integrate using the configured strategygit pull origin mainorgit pullThe result depends on your branch and pull configuration.

Configure Git

Set repository or user-level options and shortcuts.

  • Set a repository-specific namegit config user.name 'Your Name'
  • Set a value globallygit config --global <key> <value>
  • Add a short aliasgit config alias.st status
  • Read configuration helpgit help configorman git-config

Important files

Know where Git keeps repository settings and ignore patterns.

  • Repository configuration.git/config
  • Typical global configuration file~/.gitconfig
  • Ignore patterns for untracked files.gitignore
