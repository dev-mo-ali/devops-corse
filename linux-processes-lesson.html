Foundation

Three words, three viewpoints

These terms overlap because they describe different aspects of the same application.

WHAT RUNS

Process

A running instance of a program. It has a PID, memory, an owner, and a state. php artisan migrate creates a process that exits when done.

HOW IT WORKS

Daemon

A program intended to do ongoing background work. Nginx waits for HTTP requests; sshd waits for SSH connections.

HOW IT IS MANAGED

Service

A function provided by the system. A manager such as systemd starts and monitors it using a unit such as nginx.service.

Nginx illustrates all three: Its master and workers are processes. It behaves as a daemon. nginx.service is the unit that manages it.

A Laravel queue worker is a useful edge case. php artisan queue:work is long-running, but when you start it in a terminal it remains attached to that terminal. Configure it under systemd and it becomes a managed background worker.

Lifecycle

What happens when you start a service?

The service manager supervises the application; it does not run the application's business logic itself.

systemctl start→systemd reads the unit→Linux starts a process→The process does the work

For a Laravel queue service, systemd can start php artisan queue:work and track its main process. When the process exits, systemd sees its exit status or terminating signal. With Restart=on-failure, it can restart after a failure, subject to other restart settings.

Inspect a service
systemctl status nginx
systemctl show nginx -p MainPID
ps aux | grep '[n]ginx'

On modern Ubuntu, systemd commonly runs as PID 1. Other Linux systems may use different service managers.

Protection

Can process A read process B's memory?

Ordinarily, no. Each process gets a separate virtual address space.

Process A · Nginx

Its code and variables
Its stack and private memory
Virtual address 0x1000

Process B · PHP worker

Its code and job data
Its stack and private memory
Virtual address 0x1000
Same Linux kernel · different memory mappings

The same virtual address can point to different physical memory in each process. The CPU's memory management unit uses page tables set up by the kernel to translate addresses and enforce read, write, and execute permissions. An invalid memory access often causes a segmentation fault.

Important boundary: Separate private memory does not mean complete security isolation. Processes under the same user may access the same permitted files, credentials, or debugging interfaces.

Communication

What can processes share?

Linux protects private memory while providing controlled ways to work together.

ResourceCan another process access it?What decides?
Private variables and stackNormally noMemory mappings and debugging permissions
Files and logsPossiblyUser, group, and file permissions
Network socketPossiblyReachability and the listening program
SignalsPossiblyProcess permissions
Shared memoryYes, when arrangedExplicit mapping and permissions

For example, Nginx cannot directly read a Laravel worker's private PHP variable. Applications can still communicate through sockets, pipes, files, databases, or deliberately shared memory. Running applications under different users can reduce unwanted sharing.

Isolation of views

Namespaces change what a process sees

A namespace gives a group of processes a separate view of part of the system. It does not create a new kernel.

UTS · hostname

Two processes on one server can see different hostnames.

Main shell: production-server · Isolated shell: testing-server

Remember: Separate private address spaces already protect process memory. Namespaces add separate views of selected system resources.

Resource control

cgroups control what processes use

Control groups group processes to account for and limit resources such as CPU and memory.

NAMESPACES

What can I see?

A group can have its own view of hostnames, process IDs, networking, mounts, or user IDs.

CGROUPS

How much can I use?

A group can have memory and CPU usage accounting and limits.

On a systemd server, services commonly belong to systemd-managed cgroups. nginx.service may contain a master and several workers. A service-level memory limit applies to processes in its cgroup.

Inspect control groups
systemd-cgls
systemd-cgtop
systemctl show nginx -p ControlGroup

A setting like MemoryMax=1G limits a service's cgroup memory to about 1 GiB. CPUQuota=100% corresponds to roughly one logical CPU of quota. A memory limit set too low can cause processes to be killed.

Putting it together

Where do Docker and Kubernetes fit?

LayerRole
Linux kernelImplements process memory protection, namespaces, and cgroups.
systemdManages services and uses cgroups; it can also use namespaces for sandboxing.
DockerManages containers using Linux isolation and resource controls alongside other security features.
KubernetesCoordinates container workloads through container runtimes across machines.

A Linux container is not a special kernel process type. Its programs are ordinary Linux processes using a chosen combination of isolation and resource controls. Containers share the host Linux kernel, while a virtual machine normally runs its own guest operating system.

Memory aid: process = running program · daemon = ongoing background program · service = managed function · namespaces = isolated views · cgroups = resource control.

Practice on Ubuntu

See the concepts yourself

Run these examples on a practice Linux machine where you have administrator access.

Lab 1 · Find a process and its service

Read-only inspection
ps -p 1 -o pid,comm
systemctl status nginx
systemctl show nginx -p MainPID
ps aux | grep '[n]ginx'

If Nginx is not installed, choose another installed service. Compare its unit with its running PIDs.

Lab 2 · Give one shell a different hostname

  1. Run hostname in your normal terminal.
  2. Run sudo unshare --uts /bin/bash to open a shell in a new UTS namespace.
  3. In that shell, run hostname testing-server, then hostname.
  4. In a second terminal, run hostname. It still shows the original name.
  5. Type exit in the isolated shell to leave it.
Inside a new UTS namespace
sudo unshare --uts /bin/bash
hostname testing-server
hostname
exit

Both shells use the same Linux kernel. The UTS namespace changes their view of the hostname. Leaving the temporary shell ends this example.

Lab 3 · Create an isolated network view

Temporary network namespace
sudo ip netns add test-network
sudo ip netns list
sudo ip netns exec test-network ip addr
sudo ip netns delete test-network

The new namespace has its own interfaces and routing table. It may initially show only a loopback interface. The last command cleans up the test namespace.

Lab 4 · Inspect service resource groups

Run systemctl show nginx -p ControlGroup, systemd-cgls, and systemd-cgtop. These show how systemd organizes services and reports their resource use.
